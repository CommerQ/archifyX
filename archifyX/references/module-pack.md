# Module pack guide

Each platform module is a **pack of small typed diagrams**, not one dense map.
Modules may nest via `children` — the side rail is a **tree**.

## Nested modules

| Case | Pattern |
|---|---|
| Flat feature | one module, several types |
| Feature with sub-concerns | parent module + `children[]` |
| Deep ops area | up to depth 4 |

Parent may keep its own `diagrams` (boundaries) while children own deep
`sequence` / `lifecycle` packs.

Output folders mirror the tree:

`modules/<parent>/<child>/index.html` + five `<type>.html` stubs.

**Pending / unplanned types always get a stub page** so navigation never 404s.
After `archifyX deliver`, rebuild — stubs are replaced by wrapped diagrams.

## Recommended type mix

| Question | Prefer |
|---|---|
| What components live in this module? | `architecture` |
| How does a change / approval / runbook proceed? | `workflow` |
| Who calls whom for one request? | `sequence` |
| How does data move / transform / land? | `dataflow` |
| What states, retries, waits, terminals? | `lifecycle` |

## Pack size

- Start with **architecture + one deep diagram** (usually `sequence` or `lifecycle`).
- Add `dataflow` when storage / PII / lineage matters.
- Add `workflow` for ops/CI/runbooks, not for code call order.
- Keep each diagram within showcase limits (≤12 primary nodes).

## Anchors

`anchors` list overview component IDs. Example: overview node `auth` → module
`identity` with sequence + architecture.

Platform pages (always generated by `build-index`, never 404):

- `modules/<id>/index.html` — type pack hub (+ nested children cards)
- `modules/<id>/<type>.html` — delivered diagram HTML, or a pending stub
- `modules/<id>/<child>/…` — same for nested nodes

Atlas `artifact` paths are the `deliver` targets; when present they are wrapped into the type page.

## Status

- `planned` — atlas row only → platform stub
- `draft` — JSON exists, not delivered → platform stub
- `delivered` — diagram HTML present and validated → wrapped viewer
- (no atlas row for a type) — hub shows **未规划 / missing** → still a stub page
